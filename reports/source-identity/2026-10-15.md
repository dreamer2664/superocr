**Verifier:** scipio · **Date:** 2026-10-15 · **Verdict: IDENTICAL — every
recorded suite dir_hash reproduces bit-for-bit from a fresh clone.**

## Claim under test

"Same bytes, same scores": the committed `dir_hash` stamps on the canonical
suites must survive regeneration from scratch with the committed tools, on a
machine that never saw the original bytes.

## Method

Fresh clone of superocr @ main `9ab638a` (no `data/` — generated, never
committed). Each suite regenerated at its seed with the committed generator;
hash computed with the committed hasher (`tools/make_suites.py::dir_hash`,
the same function `tools/s38_compare.py` and `tools/validate_report.py`
enforce); compared against the recorded values in `tools/s38_compare.HASHES`.
The generator's own double-build determinism check (`--check`: build twice
into temp dirs, compare, validate) was also run.

## Exact commands

```bash
git clone https://github.com/dreamer2664/superocr && cd superocr   # @ 9ab638a
python3 tools/make_suites.py --seed 1 --out data/seed1
python3 tools/make_suites.py --seed 2 --out data/seed2
python3 tools/make_suites.py --seed 1 --check     # OK: two builds identical (b2c460d2fb5a), bench.py --validate green
python3 -c "
import sys; sys.path.insert(0, 'tools')
from make_suites import dir_hash
from s38_compare import HASHES
from pathlib import Path
for seed in (1, 2):
    got = dir_hash(Path(f'data/seed{seed}'))
    print(seed, got, got == HASHES[seed])
"
```
